Email

Your site sends email to invite people, to reset passwords and to notify members. It sends it through a mail server: usually a mail service you have an account with.

After changing the mail settings, restart the queue worker: the mails it sends (the export and import results) use the settings it read when it started.

Mail is sent through , from Site <not an address>.
These settings are set in the site's configuration file (config.ini) or environment, which wins over what is saved here: smtp_host, smtp_password. Change them there.

Using a mail service

A mail service delivers your site's email so that it reaches inboxes. Create an account with one, then enter its values here. These are the values for the common ones:

SendGrid

Server
smtp.sendgrid.net
Port and security
587 with STARTTLS, or 465 with TLS
User name
The word apikey, exactly as written
Password
An API key that has the "Mail Send" permission

The From address must be a verified sender, or on a domain you have authenticated with SendGrid.

Postmark

Server
smtp.postmarkapp.com
Port and security
587 with STARTTLS
User name
Your Server API token
Password
The same Server API token

The From address needs a confirmed sender signature or a verified domain. Until Postmark approves a new account it sends only to addresses on your own domain.

Mailgun

Server
smtp.mailgun.org
Port and security
587 with STARTTLS, or 465 with TLS
User name
The SMTP login from the domain's SMTP credentials in Mailgun
Password
The password of that SMTP login

Domains in Mailgun's EU region use the EU host shown with the credentials. A sandbox domain sends only to recipients you have authorised.

Amazon SES

Server
email-smtp.us-east-1.amazonaws.com
Port and security
587 with STARTTLS, or 465 with TLS
User name
The SMTP user name made under "SMTP settings" in the SES console
Password
The SMTP password made with it (not your AWS access keys)

Put your own region in the host name. A new SES account is in a sandbox and sends only to addresses you have verified, until Amazon grants production access.

Brevo

Server
smtp-relay.brevo.com
Port and security
587 with STARTTLS, or 465 with TLS
User name
The SMTP login shown with your SMTP keys in Brevo
Password
An SMTP key (not an API key)

The From address must be a verified sender on a domain you have authenticated with Brevo.

Resend

Server
smtp.resend.com
Port and security
587 with STARTTLS, or 465 with TLS
User name
The word resend, exactly as written
Password
An API key

The From address must be on a domain you have verified with Resend.

So that your mail is not treated as spam

The From address must be on a domain the service is allowed to send for. Each service asks you to prove the domain is yours by adding a few DNS records where your domain is managed: usually DKIM and SPF records that the service gives you. Add a DMARC record as well (a TXT record named _dmarc; v=DMARC1; p=none is enough to start). Mail from an address on a domain you have not set up this way, or from a free address such as Gmail, is likely to be refused or to go to spam.
